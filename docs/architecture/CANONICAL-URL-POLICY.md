# Canonical URL policy — frozen at Core v1.0.0

Client-facing origin: **`https://codeoutfitters.vercel.app`**

Declared once, in [`lib/routing/public-origin.ts`](../../lib/routing/public-origin.ts), as
`CANONICAL_ORIGIN`. No other product source file may write a hostname; the guards in
`lib/routing/same-origin.test.ts`, `lib/routing/canonical-origin.test.ts`,
`app/dashboard/interaction-identity-repair.test.ts` and `app/proposal/public-surface.test.ts`
fail the build if one does.

## The eleven rules

1. **One client-facing origin.** `https://codeoutfitters.vercel.app`. The public site,
   `/login`, `/dashboard` and `/proposal/[secureToken]` are all served from it.
2. **Internal navigation is root-relative.** Every `href` and every redirect inside the
   product is a path (`/login`, `/dashboard/leads`, `/proposal/<token>`), never an absolute
   URL. A root-relative link is correct on production, on any preview and on localhost
   without a build-time decision.
3. **Responsive design uses the same domain.** One origin serves every viewport.
4. **No `m.` subdomain**, and no second hostname for the same product.
5. **No hardcoded preview or deployment hostname** in product source. Preview URLs are
   generated by Vercel and belong to review, not to code.
6. **Production aliases redirect to the canonical origin.** `middleware.ts` calls
   `canonicalHostRedirect` and answers with a 308 that preserves path and query. It fires
   only when `VERCEL_ENV === "production"`, and never for `/api`, `/auth`, `/proposal`,
   `/_next` or `/_vercel`.
7. **Preview deployments stay independently accessible.** A preview keeps its own hostname;
   a preview that bounced to production could not be reviewed.
8. **Server-generated production links use the canonical origin.** Anything unavoidably
   absolute — an emailed password-reset link, a sitemap entry — resolves through
   `publicOrigin()`, which returns the canonical origin in production, the deployment's own
   URL in preview, and `NEXT_PUBLIC_SITE_URL` or `http://localhost:3000` otherwise.
9. **Never derive an absolute URL from a request host.** `x-forwarded-host` is
   caller-controlled. `publicOrigin()` takes an environment, not a request. The host header
   is read for exactly one purpose: deciding whether the current request sits on a
   non-canonical production alias, where the redirect target is a constant.
10. **Canonical metadata uses the canonical origin.** `metadataBase` in `app/layout.tsx`,
    `app/sitemap.ts`, `app/robots.ts` and the `ProfessionalService` structured data in
    `app/(public)/layout.tsx`. `/dashboard` and `/proposal/*` are never indexed.
11. **A future domain change is an architecture decision.** Moving to `codeoutfitters.com`
    or any other domain requires a new ADR and a migration plan covering DNS, the Supabase
    redirect allow-list, `NEXT_PUBLIC_SITE_URL`, this document and the constant. Editing
    the constant alone is not a domain migration.

## What is intentionally not centralised

`app/dashboard/proposals/[proposalId]/access/access-view.tsx` builds the copyable client
link from `window.location.origin`. That is deliberate: the link is copied by a human in a
browser, so it must match the origin they are actually looking at — on production it is the
canonical origin, and on a preview a preview link is the correct thing to copy.
